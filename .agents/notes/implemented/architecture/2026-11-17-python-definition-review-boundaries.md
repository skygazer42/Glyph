# Agent Note: Python 逐定义审查与状态边界

Status: implemented

## Problem

目录和导入迁移不能证明每个类、函数和回调都已经按其真实职责审查。项目还存在无状态工具容器、忽略参数、错误请求状态、批次覆盖快照和脚本假成功等实现问题；仅统一名字无法解决这些问题。

## Decision

审查以当前第一方 Python 文件和定义为覆盖单元。先读取实现及实际调用方，再记录修改或保留理由；AST 只用于定义定位、行号、覆盖记录和源文件指纹，不作为行为正确性的证据。隐藏且被 Git 忽略的视觉验证 Python 夹具也属于源码阅读范围。最终记录位于 docs/python-audit/，每个当前类、具名函数、方法和 lambda 都有决策。

类是否保留取决于客户端、词典、索引、缓存、配置、资源生命周期或真实框架协议。无状态业务工具采用模块函数；局部纯转换可以留在其有状态所有者内作为 staticmethod。日志、ORM、Pydantic、AutoGen、fixture、生成器及装饰器的既有协议参数不按是否读取 self 或行数删除。

请求连接、附件、来源和工具计时位于当前 ContextVar 状态。SQL 工具优先使用该请求选定连接；会话缓存过期只逐出内存，持久化删除由显式删除操作拥有。消息和会话活动时间保留业务事务，快照明确归属会话的 ORM 删除级联。

完整分级索引是快照构建，批次追加只写向量库。导入命令不默认清库或制造随机检索向量，重置需要显式 --truncate；合成问答不冒充人工核验，历史报告不冒充本轮执行结果。

CLI 在首次客户端导入前加载有效配置并应用实际模型参数；客户端和服务由入口分别登记有界关闭。ASGI 入口继续以应用设置为共享模型配置源，不增加每请求模型切换。max_tokens/timeout 的构造字段已核对 AutoGen 固定版本源码；FastAPI 与 AutoGen 最低依赖声明按当前已有的 Query 模型及 GraphFlow 用法对齐，没有安装或升级环境。

## Alternatives considered

- 只格式化或机械改名：变更便宜，但无法满足用户逐文件、逐定义审核要求，也不能发现状态、数据和资源错误。
- 把所有短方法移出类、把所有无 await 方法同步化：容易破坏框架回调、fixture 与真实同步/异步边界，因此只处理实际没有协议约束的函数。
- 新建通用执行器、配置注入框架或分级增量索引：可以进一步统一接口，但需要新的产品/SDK契约。本次复用已有所有者和完整快照入口，不猜测不存在的能力。
- 自动删除重复 rule_id 的政策文件、改数据库凭据存储：会改变业务数据或密钥合同，不能以代码风格代替授权或迁移计划，因此保留并记录实际边界。

## Consequences

审查覆盖当前 197 个 Python 文件和 2747 个定义；每个定义的当前位置、理由及文件指纹可查。实现同时修复了选库上下文、超时删历史、超过百条历史截断、快照删除、数字/时间/分块/图片数据边界、模板合同、SQL 校验及脚本数据安全问题。目录决定继续遵循[包职责与内部路径整理](2026-11-17-python-package-ownership.md)。

内部 Python 名称和脚本调用方已经同步；仓库外调用方仍需要按迁移说明调整。数据库列、表名和外键定义没有迁移；ORM 关系补充和显式重置/错误处理的行为修正已经写入审查记录。

遵照用户“暂时不测试”，没有运行 pytest、lint、应用编译/导入、构建、业务脚本、SDK/数据库/模型请求、服务或浏览器验证，也未运行笔记校验脚本。只读取官方资料、审查源码和生成定义记录；运行行为与安装后的依赖组合仍待验证。R2R 外部运行环境、严格地区过滤、重复规则数据治理、分级模型装配和旧凭据存储的限制均明确记录，不能将源码审查称为投产认证。
