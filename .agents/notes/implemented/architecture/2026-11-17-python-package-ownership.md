# Agent Note: Python 包职责与内部路径整理

Status: implemented

## Problem

导入 app 会创建轻量 Web 应用并加载模型客户端，普通脚本因此依赖另一套 Web 入口。策略数据与 ORM 基类共用 models/base.py，数据库元数据的模型、校验模型和 CRUD 则按单类拆散；AgentService 的配置位于 utils。数字脚本名和 tests 中的运维脚本也模糊了执行入口。

## Decision

保留两套现有 HTTP 协议及各自入口，清除包根的应用装配副作用。策略数据使用 policy 模块，ORM 基类独立；将共同维护的数据库元数据模型和校验模型分别合并，CRUD 按连接、元数据和聊天历史维护。AgentService 配置归入 config，以实际使用者命名。内部依赖指向定义模块，迁移仓库内调用方、测试装载路径和文档，不添加无人使用的旧路径转发。

知识库共享契约位于 app/schemas/knowledge.py，路由和文档服务分别从定义处导入。数据库会话工厂先加载显式 ORM 注册模块，保留关系、表名和字段语义。SQL 服务结果归入 Text2SQL 契约，CLI 直接管理 AgentService 的初始化与关闭。未被实际调用的兼容模型、重复请求模型和会话查询方法不再保留。

脚本使用描述职责的 snake_case 名称，通过 python -m scripts.<模块> 执行，不再逐个改写 sys.path。真正的运维程序移出 tests。Python 版本继续按现有 3.10 契约处理；字段、SQL 表名和环境变量命名沿用既有合同。后续逐定义审查中的状态、资源和数据错误修正见[逐定义审查与状态边界](2026-11-17-python-definition-review-boundaries.md)。

AutoGen、MinerU 演示使用职责命名；依赖外部 core/shared 的 R2R 源码参考独立放在 examples/r2r，不机械重写未知 SDK 的序列化协议。Windows 初始化脚本直接读取已验证的配置字段，并把配置读取失败与功能关闭区分。示例命令保留有界资源清理。

## Alternatives considered

- 仅格式化、保留现有布局：变更少，但无法消除包导入副作用，也不能减少元数据维护点。
- 全量改为新领域架构：能统一目录，但会把无关的模型客户端、持久化和 Agent 框架一并搬动，增加本次无测试重构的风险，因此不采用。
- 保留所有旧模块转发：能让旧导入继续工作，但当前没有已发布 Python 包或外部调用方的证据；同步已知调用方后直接移除内部旧路径。

## Consequences

数据库元数据的维护点减少，普通包发现不再要求装配模型服务或所有知识库后端。独立资源和业务边界继续保留。目录和迁移表位于 docs/PYTHON_STRUCTURE.md，现有测试中的加载、替换路径随定义迁移，并新增无运行依赖时的包发现用例。

内部 Python 导入路径和脚本命令已迁移，仓库外自定义脚本需要更新。遵照用户“暂时不测试”，本轮只做源码核对，没有执行测试、静态检查、编译、构建、服务启动或笔记校验脚本。Pydantic 运行时类型求值、OpenAPI、ORM 元数据映射及脚本执行均尚未验证。原有前端改动保留。
