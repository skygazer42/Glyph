# Agent Note: 公众咨询与后台问答共用对话实现

Status: implemented

## Problem

现有问答页面同时承担公众咨询和后台导航。用户要求采用02现代政务布局并分别呈现后台与咨询，两个入口仍需保留现有SSE、会话、附件和政策依据能力。

## Decision

使用同一个AgentChat组件，通过workspace属性区分展示；公众入口为/agent，后台问答入口为/workbench。后台由WorkspaceLayout提供统一导航，公众拥有独立品牌栏。路由按path隔离组件生命周期，已有卸载清理负责停止请求。公众不加载数据库连接，数据库配置仅在后台问答呈现。

快捷追问在已有问题后补充内容，不静默替换草稿。测算表单以会话ID归属内存草稿；同一会话重开时沿用已填条件，新会话独立初始化。

## Alternatives considered

- 分别复制公众和后台对话页：可独立排版，但会复制会话和SSE逻辑，后续停止请求、引用与错误恢复容易分化，因此不采用。
- 保留一套带全部后台配置的问答页：改动最少，但不符合用户已确认的两类用户展示需求，因此不采用。
- 每次重开测算都从答复元数据重建表单：元数据可能不包含用户刚输入的条件，造成修改一个年度也要重填全部字段，因此使用按会话归属的前端草稿，不新增后端或存储格式。

## Consequences

公众与后台导航分开，两个入口共用请求、会话、附件和来源合同，减少SSE与错误恢复分叉。按路由path卸载使已有清理逻辑停止旧请求；知识库query切换不强制销毁父实例，从而保留筛选上下文。

R14用户选定资源工作台后，WorkspaceLayout改为全高资源侧栏，AgentChat仍共用数据流；桌面默认并列政策依据，窄屏沿用抽屉。依据仅消费真实来源，不从原型补造条款；原型里的单文件范围控件不成为未接入的业务设置，现有后端检索范围继续为权威。

本记录最初只处理展示，两个入口当时共用浏览器咨询记录。2026-11-17 用户要求增加登录后，权限和存储决策由 [工作人员认证与公众隔离](2026-11-17-staff-access.md) 更新：后台必须通过服务端Cookie认证，公众限制私有工具，咨询缓存按入口和工作人员账号分区。

测算草稿仅在当前组件生命周期内保留，不承诺跨刷新或跨路由卸载持久化；会话间不复用同一个表单对象。独立UX走查发现草稿覆盖与重测清空后，主Agent通过真实页面核验修正。

验证包括Vue编译、既有政策数据边界检查、实际公众/后台导航、流式与非流式请求、停止和失败输入保留。浏览器网络记录确认公众没有数据库调用，后台非流式请求保留connection_id与text2sql_mode。测试接口为独立内存服务，不代表真实模型或数据库联调。
