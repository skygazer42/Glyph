# Agent Note: 政策图谱使用可读的确定性布局

Status: implemented

2026-11-18：本记录的ECharts全图布局已由用户本轮明确要求的[G6渐进图谱](2026-11-18-graph-and-draft-preview.md)替代。真实数据、未知类型与来源不伪造的边界继续保留；旧截图与运行记录仅证明当时版本。

## Problem

02现代政务布局需要在宽画布里读清实体和来源。原有力布局将矩形节点缩小，却保留较大的文字并隐藏重叠标签；实际截图出现空框、越框文字和中央拥挤。项目GraphML包含185个节点、225条关系，不能只靠固定演示坐标解决。

## Decision

KnowledgeGraph中的layoutGraph按真实节点与关系计算确定性位置，节点框和文字共同参与几何尺寸。环路、多连通块与孤立实体都保留，节点不依赖政策名称定位。初始详情选择实际关联较多的实体；搜索、邻域、缩放、平移和来源继续使用同一份真实图数据。

图谱保留接口source/target关系字段的既有显示方式，不将底层undirected GraphML宣称为新的有向业务模型，也不增加编辑、推理或最短路径能力。公众与后台入口的展示边界见[对话实现决定](../architecture/2026-11-16-public-and-workbench-chat.md)。

## Alternatives considered

- 继续调力布局：适合任意关系的探索，既有代码也少；但当前矩形与文字的缩放、重叠隐藏无法保证初始可读性，因此不作为本次默认布局。
- 固定原型节点坐标：能精确还原十节点的预览，但无法覆盖项目185个节点、有环及孤立实体，因此不采用。

## Consequences

默认图谱的标签、框与方向清楚，刷新时位置稳定，代价是新增纯布局计算及几何维护。大图或手机仍需缩放与平移，不承诺在一个视口同时读清全部实体。

主Agent运行本任务verify-graph-layout.ps1，直接调用生产函数检查真实185节点/225边及合成环路、多连通、孤立和空图，验证实体覆盖、有限坐标、框不交叠与确定性。桌面与手机截图另行验证字体、箭头和视口；不以纯算法检查代替画面。
