# Agent Note: 规则测试结果绑定当前输入与已保存内容

Status: implemented

2026-11-18：保存门槛由用户要求的[草稿预览](2026-11-18-graph-and-draft-preview.md)替代；试算结果仍绑定规则版本与参数，保存确认继续独立保留。

## Problem

规则页重新组织为原文、结构化规则和测试三栏后，修改参数仍会保留旧结果；离开后台路由再返回会丢失已保存确认。引擎的INVALID_INPUT、EXPIRED和ERROR还携带说明或字段错误，仅显示状态不足以判断原因。

## Decision

测试结果归属于规则ID、输入值和当前生成内容组成的上下文。上下文变化立即清除结果并提示重新测试，异步响应回到已改变的上下文时不再展示。保存确认以规则ID和对应YAML存入已有Pinia DSL状态，跨路由保留；生成内容变化后仍需再次保存。

结果区显示实际返回的说明、字段错误与可展开的完整JSON，只有后端返回最终数值时才显示数值。数字、布尔和文本参数继续遵循接口定义，不把普通数值解释成补贴金额。

## Alternatives considered

- 修改参数时继续保留旧结果并显示提示：旧数值仍可能被误认为当前条件的结果，因此清除旧结果，只保留重测说明。
- 每次进入页面强制重新保存：会增加无意义操作，也不能证明保存内容对应当前YAML，因此保存匹配内容的确认。
- 只展示状态和最终数值：会隐藏输入校验及政策过期原因，也失去旧结果弹窗的完整查看能力，因此同时保留说明和完整返回结果。

## Consequences

生成、保存和执行仍使用现有API，不新增规则接口。浏览器回归覆盖保存门槛、修改参数后清除结果、数值输入重测、业务校验原因、完整JSON和跨路由保存确认。测试使用内存API，证明前端状态与展示合同，不证明真实规则引擎或模型计算正确性。
