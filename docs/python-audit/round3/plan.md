用户已明确要求：已声明的必需依赖直接导入，缺失直接报错；不能用 Optional Callable、None 或猜测兼容层掩盖。不能只以工具通过代替函数职责、命名与判空语义审查。

1. 先撤回第二轮“全部适用强制项已清零”的当前结论，保留原检查作为对应源码快照的历史证据。
2. 对全部 208 个文件复查命名、导入、函数职责、实际数据契约与重复 None 判断；每个候选都检查调用方和明确依赖，不按搜索结果机械替换。

4. 删除已成立契约上的 getattr、重复校验、无职责包装；变量与函数名表达真实对象/动作，主流程顺序可读。保留输入校验、未命中、资源初始化与关闭等有依据的 None 状态，保留合法 0/False/空集合。
5. 沿用两名子智能体分区所有权，主代理负责运行时及跨模块。先运行已有行为测试，再做必要变更和有价值回归；不写锁死代码形状的风格测试。
6. 完成全范围编译、语法、Ruff、mypy、离线行为与入口检查后，更新当前报告、逐文件结论与源码哈希；检查通过仍须结合具体可读性改法，不等同于无遗漏保证。

不安装、提交、推送、部署或迁移，不改前端、已有 stash 与运行副本。共享文件冲突先协调。
