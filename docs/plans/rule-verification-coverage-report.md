# 现有规则逐条核验覆盖

日期：2026-11-21。复用前两轮已取得的官网正文及审计，再由两个既有子智能体分别只读逐项复核12条住房公积金、13条车辆消费民生入口。本次没有把所有来源重新下载，也没有对并行导入的全部资料背书。

## 结论和边界

现有25条规则均有明确核验记录：23条核对了可条件试算的公式、金额、对象、日期及限制；2条仅确认官方入口和部分条件，金额依据仍不完整。不把后两条计为“金额已核实”。资格、真实材料、账户、房源、预算和审批均须另核。

| 状态 | 条数 | 范围 |
| --- | ---: | --- |
| `verified_for_estimate` | 23 | 公积金8、住房4、车辆税补5、家电数码/智能商品3、育儿2、求职1；包括全国适用规则和常州本地执行规则 |
| `manual_only` | 2 | 人才生活/租房及房票；电动自行车 |

每条记录包含核验日期、具体条款结论、公式和资格边界、官方来源及冻结正文/原始快照、计算实现版本、审计报告。详见[规则台账](../../resources/data/policy_catalog/rules_2026_manifest.json)的每条`verification`、[完整规则清单](../../resources/data/policy_catalog/FINANCIAL_RULES_20261121.md)。哈希只确认审过的版本未变，不能代替政策条款审核，更不是政府认证。

两项未完成金额依据仍保持人工核验：

- 人才：2026措施有最高1600元/月和30万元房票，但个人档位、期限及新旧废止衔接不足。不得把最高额或2021旧档当个人应得金额。人才公积金贷款是另一个具备试算依据的业务。
- 电动自行车：2026官网问答有条件，缺本期金额及活动起止；不套2025年30%/1000，不套地方智能商品15%/1500。

公积金贷款、税款、缴存、提取和还款各有金额性质。有效期字段部分是已审年度入口的边界，不据此宣布正式文件届时失效。求职规则只在2026年9月及2027年5月申报，11月不因保有规则而返回成功金额。预算和个人事实未连接实时主管系统。

## 本次发现和修正

1. 育儿已有国籍输入，但Annual只绑定常州发布会，Transition只绑定全国出生月份表转载。现补江苏/国家及常州配套官方依据，正文和原始快照一并绑定；保留全国表的真实转载发布单位。
2. 常州汽车报废、置换和电动自行车缺地区字段，manifest回退为全国。现YAML和manifest均明确`江苏省常州市`，不改全国购置税适用范围。
3. 旧系统只有适用日期和来源，没有逐条核验状态。现在列表、详情及试算结果给出核验记录，对话呈现条款核验日期和限制。
4. 修改过的规则、缺失/变更的来源、变更的实现不再继承旧结论。保存的已审规则变更后转人工；新建/修改草稿仍可在编辑器试算，但标签为未审或待复核，不用于公开对话金额答复。草稿自写`verification`不能自行获得台账核验。
5. 台账删除、撤销或降级由现有引擎下一次核验读取，不沿用旧缓存。运行中的实现指纹固定于进程加载时；仅刷新YAML、更新磁盘代码和台账不能把内存旧实现当新版本认证。更新实现后须重启服务。
6. 台账降为人工入口时，即使旧计算函数仍产生金额，也强制人工核验并移除成功金额。

独立审查发现的来源/地区及缓存问题修复后，两个审计者分别再次复查确认关闭。没有修改计算比例或新增依赖；未重置并行导入、前端或其他已有修改。

## 变更文件及简化

- `app/agents/dsl_generator/rule_verification.py`：一个只读台账类及语义指纹函数，复用现有manifest，不另建数据库或审核服务。
- `app/agents/dsl_generator/rule_engine.py`：列表/详情/结果带核验记录；保存的漂移版本转人工，草稿仍可试算。
- `app/agents/pipeline/rule_agent.py`：未审版本不输出对话金额；已审结果展示日期及人工边界。
- 5条YAML：两条育儿补来源链，三条常州车辆补地区；现有manifest及两个清单同步。
- `tests/test_rule_verification.py`：核验覆盖、改规则、自报标签、来源/实现变更删除、台账撤销降级、未重启代码及未审对话边界；原知识管线测试补完整核验契约，不删原断言。
