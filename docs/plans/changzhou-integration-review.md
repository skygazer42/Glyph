# 常州整合独立只读核验

核验日期：2026-11-21。范围为FAQResponder、官方资料共享加载器、常州向量导入脚本和MySQL种子脚本；未修改这些实现、数据、数据库或服务。本报告是唯一写入文件。资料由其他协作者并行更新，下面数量为核验时快照。

## 待处理的具体问题

### 1. [P2] SQL已有文档的新FAQ无法补入

位置：`scripts/seed_mysql_text2sql.py:258`、`:260`。

`seed_mysql`先从`docs`删除所有已存在的doc_id，然后只给剩余新文档调用`generate_qa_pairs(docs)`。因此，“文档已经入库、后来为同一来源补充官方FAQ”的正常增量流程会遗漏这些FAQ，而不是按问答身份去重补入。当前资源确实存在这类增量：一次读取中curated FAQ为146条、旧master为54条，新增92条中54条来源已出现在既有导入清单。例子是企业信用修复访谈来源 `https://www.changzhou.gov.cn/talk/message_detail.php?sort=asc&theme_id=784178892131645` 新增的信用修复、行政处罚修复和信用分级问题。

实际只读复现：使用真实`generate_documents(200)`结果，让假cursor返回全部这些doc_id为已存在，捕获bulk_insert调用而不连接/写数据库。结果文档、实体、FAQ、标签均为0行，FAQ完全没有被检查或补写；schema_hints仍为4行。现有来源即使没有任何FAQ或需要新增FAQ，这条路径仍不会修复。

最小改法：保留完整文档映射，文档与问答分别检查已有身份；FAQ以稳定的来源+问题身份幂等补写，不能将“文档已存在”当作“它的所有FAQ已存在”。

### 2. [P2] schema_hints每次重跑重复插入4条

位置：`scripts/seed_mysql_text2sql.py:262`、`:304`；表定义 `resources/database/schema/policy_qa_schema.sql:108`。

同一只读mock重跑即使所有文档都存在，仍生成并插入4条固定提示。schema_hints只有自增主键，没有table_name/column_name/hint_type等业务唯一约束，脚本也不查重。故重复运行必然累积相同提示，与文档的幂等行为不一致。这不是对未知数据库状态的猜测，而是无条件插入路径与当前真实DDL的直接结果。

最小改法：在现有连接事务内按提示业务键查重/更新，或在相应迁移中建立业务唯一性后upsert；不应为消重默认清空整库。

### 3. [P3] 合法跨地区来常业务的官方原问被黑名单误排除

位置：`app/knowledge/faq_responder.py:_applies`城市过滤分支。

当前已核验服务FAQ包含原问：

> 常州市武进区：我是一家苏州企业的财务，今年在常州市武进区有个工程项目。现在这个项目要申报个人所得税，但是申报密码忘记了，请问一定要去常州本地税务局办理吗？

将这条完整原问直接交给加载当前curated条目的`maybe_answer`，返回None。原因是query包含“苏州”，在任何匹配前即被视为异地问题排除；但问题明确询问武进项目的申报，且与已核验官方原问完全一致。这不会产生错误直答，但使真实已收录FAQ失去命中，落入较慢且不确定的检索。

最小改法：对完全一致的已核验原问保留其已有地域语境，或仅阻止相对原问新增/改变的异地限定；不要无条件把“提到异地企业”当成“申请异地政策”。

## 已发现且复核关闭的问题

初审模糊匹配会反转资格条件：

- “常州没有未结清公转商贷款还能提装修或物业费吗？”命中“常州有未结清…”并答不符合。
- “婚前房配偶在产权证上能申请常州装修提取吗？”命中“婚前房配偶不在…”并答不能。

已立即上报，父代理按实际RED回归改为严格问句身份匹配。最后只读复核，两条反义查询均返回None，原有“有未结清”原问仍正常命中，此问题不再列为待修。初审发现的“杭州市”替换长常州原问后仍模糊命中，也随严格匹配关闭。
