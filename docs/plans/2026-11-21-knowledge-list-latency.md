# 知识库列表响应优化

目标：常规进入、筛选与翻页在当前本机环境下 300ms 内显示页面/列表；完整解析、入库不作为同步按钮任务。基线 `/api/knowledge/documents` 首次 5272ms、再次 3203ms，1093 份资料，每次重新读取原件和解析正文。

## 改动边界

- 维持现有政务视觉、资料格式、认证和文档版本检查。不开新依赖、不迁移原文或索引。
- 列表从已验证的目录快照读取，使用轻量文件指纹扫描检测正常变更，仅重建变化条目；服务启动预热，持久快照避免冷启动重复全文读取。
- 打开工作区、解析、预览、入库继续校验原文/解析正文哈希；这些操作使对应目录条目失效，旧状态不能作为操作授权依据。
- 原有无分页读取兼容保留；支持服务端分页、文件名/状态筛选和排序，并返回全库统计。
- 前端迁移到分页查询，按完整参数缓存；账号退出清理缓存，切换请求取消或忽略旧响应，查询防抖，错误保持可恢复。
- 删除列表路径中的重复正文读取，不为加速移除严格操作校验。

## 验证顺序

1. 基线知识工作区回归，新增缓存失效、完整哈希校验与分页契约用例，先复现性能路径每次全文读取。
2. 后端：未变更的重复列表不读正文；更改/删除/上传/重解析/入库更新条目；同 mtime 内容修改在严格工作区与入库校验中仍能检测；非法查询不进入扫描，公众无权限。
3. 前端：分页与筛选正确、缓存隔离和过期、旧响应不覆盖新查询；静态检查、生产构建。
4. 运行服务实测首屏/热请求/筛选/翻页，浏览器观察按钮反馈与真实列表。记录中位数与最慢值，不把骨架出现当列表完成。

## 分工

主代理负责目录快照、API、启动预热、相关 Python 回归与整合验证；独立前端代理只负责知识库页、knowledgeApi、Pinia 列表状态和必要脚本测试。
