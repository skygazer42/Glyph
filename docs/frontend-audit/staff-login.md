# 工作人员登录

本次为存量产品增加登录流程；沿用 R14 01 资源工作台、R16 02 经纬标记、现有 Element Plus 组件与明暗主题变量。

工作人员要在确认身份后处理政策资料、咨询与规则。公众咨询始终从 `/agent` 进入；后台入口先进入独立登录页，服务端确认会话后再显示原工作区。

## 流程

- `/workbench`、`/knowledge`、`/graph`、`/dsl` 在页面挂载前检查服务端曾确认的身份及实时到期时间。未知或过期时立即进入 `/login`，由登录页恢复 Cookie 会话，避免后台内容先显示或长时间空白。
- 登录页只收集账号与密码，Enter 提交。恢复会话和提交期间控件禁用并显示进度；错误使用表单旁的中文反馈。提交被拒绝后保留账号、清空密码并将焦点返回密码框；离开页面也清空密码。
- 原工作区路径、文档与检索查询参数保留。返回地址仅接受四个真实工作区路径，拒绝外部地址、登录循环、路径穿越与控制字符；无效地址进入知识库。
- 身份来自 `/api/auth/login` 或 `/api/auth/session`，不使用前端角色标记或本地成功回退。新确认的账号与本窗口上次确认账号不同时，先清理私有 Pinia 状态再进入后台。
- 页头显示真实姓名或账号与明确的“退出”操作。只有 `/api/auth/logout` 返回 `success: true` 后才清空认证、私有 Pinia 状态和该账号的本地聊天记录；服务失败保留当前状态并显示错误。服务端退出成功而浏览器记录清理失败时，仍进入登录页并说明实际清理问题。
- 退出请求返回401表示服务端已不接受该身份，此时清理本地状态并显示登录过期；不将网络失败或503当作退出成功。

## 表单与状态

品牌、主操作色、文字与表面均使用现有 `--wb-*`、`--platform-mark-*` 变量；页面样式局部作用，不引入组件库或新样式系统。手机表单输入为 16px，输入与提交保留 44px 高度；后台手机页头允许两行排列以容纳账号和退出。

键盘焦点使用现有青蓝变量的清晰轮廓；账号和密码使用真实标签及浏览器自动填充语义，密码显示由 Element Plus 提供。必填错误落在字段附近，登录失败用 `role="alert"`，过期提示用 `role="status"`。未添加入场动画，等待反馈使用组件原有加载状态。

认证只使用同源 HttpOnly Cookie。密码、JWT 与 CSRF 不写入 Local Storage；CSRF 仅保存在当前 Pinia 实例，退出请求通过 `X-CSRF-Token` 发送。认证请求直接使用 `fetch`，8 秒超时，不依赖业务请求模块。
