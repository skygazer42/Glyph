# R20 知识图谱与规则工作台

本轮按用户提供的两份专业工具页建议实施：G6 v5 + 全工作区画布 + 渐进子图，以及等高规则编制/试算工作台。继续使用 Vue 3、Element Plus、经纬Logo及青蓝品牌；没有引入参考代码中的模拟政策、比例或金额。

| 编号 | 意见 | 落地位置与结果 |
| --- | --- | --- |
| 1 | 图谱被普通居中容器束缚 | KnowledgeGraph.vue / modules.css：解除管理页限宽与内边距，画布撑满模块；HUD检索、层级、图例、缩放/适应/全屏/刷新与可收起详情 |
| 2 | 全图过密、加载与搜索脱节 | GraphML后端新增subgraph/search，G6普通局部实例，首屏24核心节点（窄画布12），按实体搜索与1–3层查询，双击或详情展开一跳，revision隔离、600节点合并上限 |
| 3 | 图例与详情无法解释关系 | 按接口类型映射尺寸和色相，平行边分弧、自环保留，方向仅服从真实GraphML；选中一跳聚光灯，缩放降低文字密度，来源标识折叠，详情保留完整名称和相邻关系 |
| 4 | 规则两栏空洞、主按钮冲突 | DSLGenerator.vue：两栏stretch等高，试算空态呈现真实操作步骤；保存描边，生成唯一实心主动作；禁用态统一置灰，输入不可拖拽，代码/错误详情共用等宽字体 |
| 5 | 必须保存才试算 | 新增POST /api/dsl/preview，校验YAML后用当前规则引擎纯内存计算；不创建目录、不保存文件、不改共享规则。前端草稿调用preview、已保存规则仍按ID测试，参数与当前生成YAML一致 |

图谱引擎为安装的 `@antv/g6` 5.1.1，保留ECharts供其他图表使用。按官方数据、视口、平行边与布局API接入，核对本机包的声明和实现；未采用原建议未经测量的300ms/固定FPS承诺。语料存在泛化类型时不据名称猜测为政策或条件，未知类型显示为其他实体。

当前本地服务8018在真实认证之外，挂载只读GraphML和草稿试算；完整模型、资料处理、规则生成/保存/列表服务仍未启动，对应接口返回503。使用Glyph独立Python3.11虚拟环境及最小服务依赖，不更改其他项目环境。

## 本轮证据

现有文件返回185实体，桌面首屏24；从全图搜索“商务局”定位济南市商务局得到29实体，选择市财政局后显示3个未展示关联；展开后为32实体，市财政局相邻关系从1条变为4条。层级选择、缩放与详情在真实页面操作，未写入图谱或业务数据。

源码复核修正了：展开固定120导致高连接节点无法继续展开、概览选中后切层级不查询、返回概览失败时提前改标题、旧绘制迟到调整新视口。实际画面修正了布局回写导致圆点膨胀、检索控件占满两行、长chunk标识挤占关系详情。

独立视觉首轮指出手机鸟瞰的机构锚点过小、桌面次要标签重叠。修正逆缩放字号与G6内置标签避让后，单次图像复核确认可读性阻断清零、桌面名称不再相互覆盖、规则列表单一错误说明和重试完整可见。简介`<SEP>`已按真实分隔符换段，最终选中态由主Agent查看；评审没有运行交互或检查代码。

截图和前后对比位于 `.oil-ui/graph-rules-r20/shots/`，桌面1440×900、手机390×844。前后图谱数据状态不同（旧版为连接失败，新版为真实只读GraphML），对比只证明布局与当前实现，不把数据成功当成纯样式收益。
