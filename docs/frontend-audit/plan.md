## 执行顺序

1. 固定 Git 起始状态与文件清单；读取 package、构建配置、调用合同及规约证据。
2. 运行现有生产构建作为基线；没有现成 lint/typecheck/test 时如实记录，复用已装编译器和 Node 验证。
3. 按独立写入责任分区审核：全部 views、全部 components；主智能体审核其余文件。
4. 各区在编辑前写出具体修正计划；涉及状态、请求、资源生命周期的行为修复先复现或补最小回归，再改代码。
5. 主智能体审核入口、路由、全局样式与配置；收集每个文件的规则、问题、最小修正及验证结果。
6. 集成检查全部 diff，运行生产构建、Vue/JS/CSS 静态解析、行为回归与可用的真实浏览器验证。
7. 生成 schemaVersion 2 写法证据单，绑定最终文件范围和 SHA-256；逐项记录新增/改名标识符及来源。
8. 核对文件清单无遗漏，交付变更文件、简化内容、验证证据和剩余限制。

## 基础层编辑前发现与最小修正

- `useTheme`：两个独立 ref 代表同一个全局主题，系统监听无法卸载；共享状态、同引用清理，持久化失败仍允许内存主题切换。
- `useLocalStorage`：默认数组被复用污染；持久化会话的多个消费者快照分裂；克隆 JSON 默认值、校验缓存形状，列表操作先同步存储再发布共享状态，写失败向调用方传播。
- `request`：`||` 丢失合法重试次数/延迟 0；主动取消仍重试并弹错；写请求网络失败自动重放可能重复提交。保留返回值/显式重试接口，默认只重试读取，取消直接拒绝。
- `app` store：通知旧计时器可能提前关闭新通知，且 store 销毁无清理；替换前取消、scope dispose 清理。
- `App`：重复根 id、无用 route 绑定与导航调试输出；删除冗余项。
- 全局 CSS：伪元素盒模型未继承全局 border-box；补全选择器。原生交互可见焦点统一使用现有主题色。
- 其他入口/路由/配置：完整阅读及编译核对；无已证实问题的实现保持不变。
