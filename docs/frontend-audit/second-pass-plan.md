# 第二轮：全部前端维护文件写法修正

用户将范围明确为 `F:/Glyph/web` 全部维护文件；本计划替代首轮“无问题保留”策略。沿用已有业务、公开接口、Vue 3、Element Plus、无分号 JS、单引号、2 空格及 scoped CSS，不新增依赖。

## 编辑前计划

1. 复用 2 个子智能体：组件 15 文件、页面 5 文件；主线负责其他 16 个文件和集成。每个文件按实际适用规则改写，删除错误注释也记录为简化，不虚构缺陷。
2. API 对保存数据使用对象解构；请求错误处理、存储校验和清理分支展开为明确块，保留重试、取消、持久化失败及共享状态合同。
3. 主题初始化布尔改为 `isInitialized`，路由参数、图标名采用实际含义；DSL 文本判断表达非空字符串；入口和路由去掉仅转发的局部绑定。
4. App 装饰图标隐藏于辅助技术，副标题采用段落；HTML/CSS 按层级、选择器和长值排版，保持样式计算结果与主题变量名。
5. Vite 配置改用原生 ESM 文件 URL 解析，package 明确模块类型及已安装 Vite 的 Node 引擎范围；lockfile 只同步根包元数据，不改依赖树。
6. 将现有 Vue/JS/CSS/HTML 静态编译检查收拢为 `web/scripts/check.mjs`，提供 `npm run check`，可在 Docker 构建前运行；审计脚本复用此入口并补 Git diff 检查。新增脚本也纳入全量清单与命名记录。
7. Nginx 配置沿用当前合同，只将缩进统一为项目 2 空格，不顺带改变代理或超时行为。Docker 仅增加静态检查门槛，不改镜像版本。
